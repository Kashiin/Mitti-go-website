# SEO implementation report — Mitti GO

Source of requirements: `SEO_FULL_TZ_Mitti_GO.md`. Date: 2026-09-26.

## 1. What was found (before)

| Area | State |
|---|---|
| Hosting | GitHub Pages with custom domain (`CNAME` = `mitti-go.uz`). No Apache, so `.htaccess` is not used. |
| Architecture | Hand-written static site: one `index.html`, plus `blog.html` and `post.html?p=<slug>`. |
| Languages | RU in the HTML; UZ/EN swapped in by JavaScript (`T` dictionary in `script.js`). One URL for all three languages. |
| Blog | Posts only in `assets/js/posts.js`; cards, article text, H1 and dates rendered by JS. Articles lived at `post.html?p=…` (query URLs, not crawlable as separate pages). |
| Head | Only `<title>Mitti GO</title>` and a short description. No canonical, hreflang, Open Graph, Twitter card or JSON-LD. |
| Files | No `robots.txt`, `sitemap.xml`, `site.webmanifest` or `404.html`. Favicons in `assets/images/`. |
| Images | Logos 2170×725 PNG (~1 MB each) shown at 40 px; the light and the dark logo were both downloaded. Many `<img>` without width/height. |
| Headings | The three facts right under the H1 were H3 (skipping H2). Footer column titles were H4. |

## 2. What was implemented

- **Static generation.** `tools/build.mjs` (Node) renders every page from `src/` at build time. Titles, descriptions, H1/H2, article text, dates and links are all in the HTML — nothing SEO-relevant depends on JavaScript.
- **Separate URLs per language.** Landing: `/uz/`, `/ru/`, `/en/`. Blog: `/uz/blog/`, `/ru/blog/`, `/en/blog/`. Each article has a localized slug per language (21 article pages).
- **`<html lang>`, a self-referencing canonical (absolute https, never `/index.html`), reciprocal hreflang uz/ru/en + x-default** on every indexable page.
- **Unique title, meta description and a single H1** on every page. Landing texts are taken from the brief:
  - RU title: «Mitti GO — безопасное видео для детей | Родительский контроль»; H1: «Безопасное видео для детей — только то, что выбрали родители».
  - UZ title: «Mitti GO — bolalar uchun xavfsiz video | Ota-ona nazorati»; H1: «Bolalar faqat siz tanlagan videolarni ko‘radi».
  - EN title: «Mitti GO — Safe Videos for Kids | Parental Controls»; H1: «Safe videos for kids — chosen by parents».
  - The screen-time article uses the title and description from the brief (§13).
- **Open Graph** (`og:site_name/type/title/description/url/image/image:width/height/alt/locale` + alternate locales) and **Twitter `summary_large_image`** on every page. Articles use `og:type=article` with `article:published_time` and `article:modified_time`.
- **Open Graph images 1200×630**: `/assets/og/mitti-go.jpg`, `/assets/og/blog.jpg`, `/assets/og/post-<id>.jpg` for every article.
- **JSON-LD**:
  - Landing: `Organization`, `WebSite`, `WebPage`, `SoftwareApplication` (free-plan offer, no ratings/reviews/download counts), and `FAQPage` built from the FAQ that is visible on the page.
  - Blog index: `Blog` (with the list of `BlogPosting`s) and `BreadcrumbList`.
  - Articles: `BlogPosting` (headline, description, images, datePublished, dateModified, inLanguage, articleSection, wordCount, author/publisher Organization with logo, mainEntityOfPage) and `BreadcrumbList`.
- **Visible breadcrumbs** on the blog and article pages: «Главная → Блог → Статья».
- **Internal linking**:
  - Landing → blog (menu, «Все статьи» button, the three latest posts).
  - Blog → every article.
  - Article → «Другие статьи» sidebar, «Читайте также» (3 related), CTA «Попробуйте Mitti GO» to the landing in the same language, button back to the blog, links inside the text to landing sections.
  - Footer on every page → landing sections (how it works, permissions, player, screen time, plans, parents, safety & privacy, Android TV & devices, FAQ), the 3 latest posts, the blog, and the same page in the other two languages.
- **Language switcher = real links** (`<a href hreflang>`) to the equivalent page in the other language. The choice is remembered for the next visit to `/`.
- **`/` = x-default** language chooser: three crawlable links plus a short script that sends visitors to their saved language, else the browser language, else Russian. Old anchors keep working (`/#faq` → `/ru/#faq`).
- **Branded `404.html`** (noindex) with links to the home page and the blog in all three languages.
- **Legacy URLs**: `blog.html` and `post.html?p=<old-id>` are small noindex pages with canonical, meta refresh and a JS redirect to the new URL (per-post map generated by the build).
- **`robots.txt`**, **`sitemap.xml`** (28 URLs with `xhtml:link` hreflang alternates and `lastmod`), **`site.webmanifest`**.
- **Favicons/icons** at the site root: `favicon.ico`, `favicon-16x16.png`, `favicon-32x32.png`, `apple-touch-icon.png`, `android-chrome-192x192.png`, `android-chrome-512x512.png`, `maskable-512x512.png`.
- **Semantic HTML / headings.**
  - `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`.
  - The three facts under the H1 are now H2; footer column titles are H2; card titles are H2 on the blog page and H3 inside H2 sections.
  - The visual style is kept via CSS.
- **Images.**
  - Every `<img>` has `alt` (informative where the picture carries meaning, empty for decoration) and `width`/`height`. The build reads real image sizes automatically.
  - Images below the fold use `loading="lazy"` and `decoding="async"`.
  - The article cover (LCP) is `fetchpriority="high"` and not lazy.

## 4. Redirects

GitHub Pages has no server-side redirect rules (no `.htaccess`, no `_redirects`). What is covered and how:

| Requirement | Solution |
|---|---|
| `http → https` | GitHub Pages «Enforce HTTPS» (setting, see manual actions). 301 by GitHub. |
| `www → non-www` | GitHub Pages redirects `www` to the apex from `CNAME` automatically once the `www` DNS record exists (see manual actions). |
| `/index.html → /` | Not possible as a 301 on GitHub Pages: `/index.html` is the same file as `/`. It is not a separate page — the canonical everywhere is `https://mitti-go.uz/`, and no link or sitemap entry uses `/index.html`. |
| `/ru` → `/ru/` (no slash) | 301 by GitHub Pages automatically. |
| Old `blog.html`, `post.html?p=…` | Client-side redirect pages (noindex + canonical + meta refresh + JS), one hop, no chains. |
| Unknown URLs | GitHub Pages serves `/404.html` with a real HTTP 404 status. |

If the site ever moves to a server with rewrite rules, replace the legacy pages with 301s and add `/index.html → /` there.

## 5. Blog — how it is indexed now

- `/{lang}/blog/` lists all posts as real `<a href="/{lang}/blog/<slug>/">` cards with title, excerpt and date in the HTML.
- Each article is a separate `index.html` with the full text, H1/H2, dates (`<time datetime>`), breadcrumbs, related posts and CTA.
- No hash URLs, no modals, no JS-only content. Scripts only run the interactive demo phone, the theme switch and the mobile menu.

## 6. Articles — how new ones are created

Add one object to `src/posts.js`: `slug` (id), `slugs {uz,ru,en}`, `date`, optional `updated`, `cover`, optional `imageAlt`, `tag`, `title`, `excerpt`, `body`, and optionally `seo {title, description}` and `related` (ids). Then run:

```powershell
python tools/images.py   # Open Graph image from the cover
node tools/build.mjs     # pages + sitemap + redirects map
```

The build validates slugs (latin, unique) and required texts in all three languages. For every article it generates the metadata, canonical, hreflang, OG, Twitter, JSON-LD, sitemap entry, blog card, footer link, related-post links and the legacy redirect.

## 7. Sitemap / robots

- `robots.txt`: `User-agent: * / Allow: /` + `Sitemap: https://mitti-go.uz/sitemap.xml`. Nothing is blocked.
- `sitemap.xml` is generated on every build: `/`, 3 landings, 3 blog indexes, 21 articles, with hreflang alternates and `lastmod` (article dates; build date for landings).
- Excluded: `404.html`, the legacy redirect pages, `/index.html`.

## 8. Performance

- Logos 2170 px (≈1 MB each, both variants downloaded) → 449×150 / 439×150 (≈70 KB). About 1.9 MB less on every page view.
- Mascot 800 → 640 px.
- Landing loads **one** script (`script.js`, deferred) instead of three. The posts data (~100 KB) and the blog renderer are no longer shipped to browsers.
- Blog and article pages load a 1.5 KB `site.js` (deferred) instead of the posts data plus the renderer.
- `width`/`height` on all images (CLS); lazy loading below the fold; the article cover prioritised.
- The saved theme is applied in `<head>` before first paint (no light/dark flash).
- CSS is cache-busted per build (`styles.css?v=…`).
- Fonts: Nunito with `display=swap` and preconnect (unchanged). Material Symbols keeps `display=block` on purpose: with `swap`, icon ligature names would flash as text.

## 12. Decisions and open points

- **x-default at `/`** is a chooser with a JS redirect (standard locale-redirect pattern). `/` stays indexable with its own title; the language pages carry the real content. Alternative, if preferred later: make `/` a full landing in one language.
- **Hero H1** was changed to the H1 from the brief in all three languages; the rest of the landing copy is unchanged.
- **Privacy Policy, Terms of Use, Contacts** — the site has no such pages and no contact data, and legal texts should not be invented. The footer is ready to take the links once texts and contacts exist; add them as pages in `src/templates/` and to the build/sitemap.
- **Article facts:** no new medical or scientific claims were added; article texts are the existing ones.
- **Android TV:** the landing has a section (`#devices`) that the footer links as «Android TV и устройства»; there is no separate Android TV page, so none was created (no doorway pages).

## 13. Manual actions (outside the repository)

1. **GitHub → Settings → Pages:** confirm the custom domain `mitti-go.uz` and tick **Enforce HTTPS**.
2. **DNS:** apex A/AAAA records to GitHub Pages and `www` CNAME → `<user>.github.io`. GitHub then redirects `www` → apex.
3. **Google Search Console:** add the domain property `mitti-go.uz` (DNS TXT verification), submit `https://mitti-go.uz/sitemap.xml`, run URL Inspection for `/`, `/ru/`, `/uz/`, `/en/`, the blogs and the articles.
4. **Bing Webmaster Tools:** add the site (or import from Search Console) and submit the sitemap.
5. **Yandex Webmaster:** add `mitti-go.uz`, verify (DNS/meta) and submit the sitemap.
6. Check the pages in the **Google Rich Results Test** / Schema.org validator after deploy.
7. Run **PageSpeed Insights** (mobile and desktop) on production.
8. Provide Privacy Policy / Terms / Contacts content when available.
